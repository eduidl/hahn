# Hahn

ローカルMCAPをRustでデコードし、ブラウザへ逐次配信するプロットビューワ。

## 起動

Rust 1.95以上、Node.js 22.12以上（または20.19以上）が必要です。
`Cargo.toml` は手元の `~/repos/eduidl/mcapdecode-rs/mcapdecode/mcapdecode` を相対パスで参照しています。
別の場所にチェックアウトした場合は、この依存パスを変更してください。

```bash
cd web
npm ci
npm run build
cd ..
cargo run --release -- --data-dir "$HOME/repos/eduidl/mcapdecode-rs/data"
```

<http://127.0.0.1:3000> を開き、録画と数値フィールドを選択します。
初回にros2.mcapを選択し、録画全体の時間軸を設定します。録画の変更はヘッダーのフォルダーアイコンから行い、受信したデータから順次描画します。

- 中央エリアはTIME SERIES・STATE TRANSITIONウィジェットを上下左右に分割して配置します。ヘッダーの「ウィジェットを追加」で種類の一覧を開き、既存ウィジェットへドラッグすると、ドロップ位置に最も近い辺（左右上下）の側へ分割して空のウィジェットを追加します。ウィジェットがないときは中央エリアへドロップします。タイトルバーをドラッグして組み替え、境界線でサイズを変更できます。中央エリアの全体サイズは表示領域に固定し、分割を増やしてもスクロールせず各ウィジェットが縮みます。
- 各ウィジェットの最大化ボタンで一時的に中央エリア全体へ広げられます。同じボタンまたはEscapeで元の配置に戻り、表示範囲と取得済みデータは維持します。
- 各ウィジェットのメニューから左右分割・上下分割・ウィジェットの変更・クリア・削除ができます。「ウィジェットを変更」にポインタを合わせると右（右端では左）にサブメニューが開き、別の種類へ切り替えます。切り替え先で表示できない系列は外れ（サブメニューに外れる系列数を表示）、表示範囲は初期状態に戻ります。クリアはそのウィジェットの系列をすべて外して表示範囲を初期状態に戻し、型の制約も未指定に戻します（横軸の時刻表示などの設定は維持）。系列がないときは無効です。分割は元のウィジェット（種類・系列・色・線幅・表示状態・横軸の時刻表示）を複製します。複製先の軸は初期状態です。空のウィジェットが必要ならクリアするか、「ウィジェットを追加」から配置します。
- クリックで設定対象を選択し、歯車ボタンで左のパネル設定を開きます。フィールドのドロップは対象ウィジェットだけに適用し、サイドバーのタブは切り替えません。
- パン／ズーム・リセット・系列の表示設定はウィジェットごとに独立します。同じフィールドの取得データは共有し、配置・サイズ・表示設定の変更では再取得しません。
- 録画変更時は配置を維持し、系列と軸を初期化します。今回の配置・設定は保存せず、ページ再読み込みで空のウィジェット1つに戻ります。タブ収納は未対応です。

- 複数のトピック・数値フィールドを重ね描き。
- TIME SERIESは数値・bool・enumを表示します。系列のない状態では全型を受け付け、最初に追加した系列の型（数値／bool／定義が一致するenum）だけを重ねられます。系列をすべて削除すると再び全型を受け付けます。bool・enumは縦軸を離散値で表示します。STATE TRANSITIONはbool・enumを1系列1行で表示し、型やenumの定義が異なる系列も並べられます。
- ホイールは横軸だけ、Shift＋ホイールは縦軸だけをマウス位置中心で拡大縮小。片方の操作で他方の範囲は変更しません。
- ホイール1イベントにつき拡大は1.1倍、縮小はその逆数を掛け、両軸とも1倍を下限とします。
- ドラッグは標準でパン（横・縦方向の移動）。「パン／範囲ズーム」ボタンでモードを切り替え、範囲ズームでは横方向にドラッグして時間範囲を拡大します。ホイール操作はどちらのモードでも共通です。
- パンの移動範囲は両軸とも制限しません。1倍のままでも録画範囲の外へ移動でき、移動先でズームしても位置を元の範囲に引き戻しません。
- 横軸の表示は標準でブラウザのローカルタイムゾーンの実時刻（日付・ミリ秒付き）です。パネル設定の「横軸の時刻表示」で録画開始からの秒数に切り替えられます。表示形式はウィジェットごとに独立し、変更しても表示範囲や取得データは変わりません。
- 横軸は録画全期間、縦軸は取得済み全点の範囲を基準（1倍）とします。表示操作を始めた時点で縦軸の基準も固定し、時間範囲に合わせた自動リスケールは行いません。
- ダブルクリックまたは「リセット」で両軸の倍率・位置を戻します。縦軸の基準は、その時点で取得済みの全点から更新します。読み込み中は、表示操作をするまで新しいデータに合わせて初期範囲を広げます。
- 初期表示ではリセットボタンは無効です。表示範囲を変更すると有効になり、リセット後は再び無効になります。
- カーソルで最寄りのサンプル値を確認。パネル設定で系列の表示を切り替え。
- 左カラムは「パネル設定」「トピック」「エラー」の3タブ。数値フィールドをプロットまたはパネル設定へドロップして追加できます。パネル設定の「＋ フィールドを追加」で、選択中のウィジェットに今追加できるフィールドだけを検索欄付きの一覧で開き、選ぶ（またはEnterで先頭を選ぶ）と追加して閉じます（候補は録画ごとに事前計算した索引から絞り込みます）。パネル設定には選択した系列の読み込み状況・表示切替・削除・色・線幅（Time Seriesのみ）の設定をまとめ、フィールド選択のチェックボックスは設けません。トピック自体はルートメッセージのstructとして扱い、プロット系ウィジェットには追加できません。トピック一覧はパネルと独立した共通設定で、選択チェックボックスは持たず、ドロップしてもタブは切り替えません。文字列・配列・構造体なども表示・ドラッグでき、ドラッグ中は各ウィジェットに追加できるかを表示し、追加できないウィジェットには理由を表示してドロップを受け付けません。スクロール領域はバーの幅を事前に確保します。
- 読み取り不可トピックは初期状態で非表示。「エラーのあるトピックを表示」のチェックボックス1つで一括表示を切り替え、理由はトピックの展開部分とエラータブに表示します。
- 開いている録画のファイル名はヘッダー中央に表示します。受信中は下部ステータスの「停止」で全ウィジェットの受信を中断できます。ズーム・パン・系列の表示切替では通信せず、取得済みデータを使います。

サーバは既定でlocalhostのみで待ち受けます。`--listen` と `--web-dir` で変更できます。
開発時はサーバを起動したうえで `cd web && npm run dev` を実行します。Viteは `/api` をポート3000へ転送します。

## 実データでの検証

通常の操作確認には `~/repos/eduidl/mcapdecode-rs/data/` の録画を使います。元ファイルをコピー・変更しません。

- `protobuf.mcap`: `/chassis` の `speed`、`throttle` など。
- `ros2.mcap`: `/pose` の `pose.position.x`、`pose.position.y` など。
- `ros2msg_test.mcap`: `/example/sample` の `x`、`value`。

```bash
cargo test --test real_data -- --ignored
```

このテストは配信された最初のサンプルを、ライブラリの直接デコード結果と照合します。
別の保存先を使う場合は `MCAP_TEST_DATA_DIR=/path/to/data` を指定できます。
読み取れないトピックは初期状態でトピック一覧から隠し、エラータブに理由を表示します。「エラーのあるトピックを表示」をオンにすると「読み取り不可」と表示します。スキーマencodingが空のトピックなどを推測でデコードしません。

## 自動テストと境界条件用データ

```bash
mkdir -p /tmp/hahn-demo
cargo run --example generate_demo -- /tmp/hahn-demo/demo.mcap 30000
cargo run -- --data-dir /tmp/hahn-demo
cargo test
cargo clippy --all-targets -- -D warnings
cd web
npm test
npm run build
```

生成データは境界条件の再現用です。2トピック、各30,000サンプル（300秒）を生成し、NaN、欠損したネスト構造、逆転・重複した時刻、JavaScriptの安全な整数範囲を超える値を含みます。

## 構成

- `src/recording.rs`: mmapしたMCAPのSummaryを読み、StatisticsまたはChunkIndexから時間範囲を取得するアダプタ。
- Rust API: `mcapdecode-rs` のROS 2 msg/IDL・Protobufデコーダを利用。構造体内の数値スカラーをフィールド名の配列で指定。
- 配信: トピックごとのHTTP POSTにNDJSONで応答。1024メッセージまたはコールバック時点で100msが経過したらバッチを送信。圧縮チャンクの読み取り・デコード中はバッチが遅れる場合があります。
- フロント: React＋TypeScript＋Canvas 2D。受信による描画更新は最大10回／秒。ファイル順のデータを時刻順に安定整列し、重複時刻を保持。選択したフィールドは全期間を取得して録画ごとに保持し、ズーム・パンは描画範囲だけを変更。追加フィールドだけを取得し、既存系列を読み直しません。キャッシュは録画切替で破棄します。
- バックプレッシャー: 4バッチのキューで読み取り速度を制御。クライアント切断後、次のメッセージコールバックで読み取りを停止。

元の整数値とナノ秒時刻は文字列で保持します。描画座標の数値変換では64bit整数が丸められる場合がありますが、カーソル表示の元値は保持されます。欠損値・非有限値は線の切れ目になります。

## API

`GET /api/files` は起動時に発見したMCAPの `id`、相対ファイル名、バイト数を返します。サブディレクトリも探索し、シンボリックリンクは辿りません。IDは起動中のみ有効です。新しい録画の追加後はサーバを再起動してください。

`GET /api/files/{id}` は `start_ns`、`end_ns`（最終時刻を含む）、`message_count` を返します。StatisticsがなければChunkIndexの時間範囲を使い、件数はnullになります。

`GET /api/files/{id}/topics` はトピック名、スキーマ名、メッセージ数、全フィールドのパス・型一覧、トピック単位の非対応理由を返します。

`POST /api/files/{id}/series`:

```json
{
  "topic": "/telemetry",
  "fields": [["signal"], ["position", "x"]],
  "start_ns": "1760000000123456789",
  "end_ns": "1760000001123456789"
}
```

時間範囲は `log_time` の開始以上・終了未満。上下限は省略可能で、最終時刻を含めるには `end_ns` を省略します。フィールド数は1〜64。

応答は `application/x-ndjson`:

```json
{"type":"batch","rows":[{"time_ns":"1760000000123456789","values":[14.0,5.0]}],"scanned_messages":1}
{"type":"complete","scanned_messages":1}
```

`values` は要求したフィールド順。i64/u64は文字列、その他の数値はJSON number、欠損値・非有限値はnull。
配信途中の失敗は `{"type":"error","message":"..."}` で終了します。`complete` がないままの切断もクライアントでエラーとして扱います。
`scanned_messages` はそのリクエストの選択トピック・時間範囲に一致した件数で、録画全体に対する進捗率ではありません。

## 前提と制限

- 起動中のMCAPは変更・上書き・切り詰めをしないでください。mmapと既存Readerの前提です。
- Summary、ChunkIndex、対象チャネルのメッセージ索引を持つ、チャンク化された録画を対象とします。未対応の形式や同一トピックに複数チャネルがある場合は理由を表示します。
- ライブ配信、GCS固有のアクセス、認証、配列展開、式、XY表示、複数パネルは対象外です。GCSFuse経由でも通常のファイルとしてアクセスしますが、その環境での性能は別途測定が必要です。
- 全期間のプロットには選択トピックを含むチャンクを読み取ります。異なるトピックのリクエスト間でチャンク解凍は共有しません。
- 初版は全点を転送・保持します。ブラウザのメモリはその録画で取得したフィールドの総点数に比例します。一度取得した系列は選択を外しても再利用のため保持し、録画切替で破棄します。

## 実録画での測定

releaseビルドで起動し、実際のトピックとフィールドを指定してください。

```bash
python3 scripts/measure_stream.py http://127.0.0.1:3000/api/files/0/series \
  --topic /chassis --field speed --field throttle
```

スクリプトは最初のバッチまでの秒数、完了までの秒数、転送バイト数、行数を表示します。
サーバの最大RSSは `/usr/bin/time -v target/release/hahn --data-dir ...` で起動して終了時に確認できます。
ブラウザでは開発者ツールのPerformance/Memoryで、全期間読み込み・ズーム・中断時の操作性とメモリを確認します。初回とOSキャッシュが効いた2回目を分けて測定してください。
