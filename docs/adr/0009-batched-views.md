# 0009. 同じ範囲のビューを一つのリクエストで読む

状態: 採用（2026-11-03）

## 背景

録画は複数のトピックをまとめた圧縮チャンクで保存される。近い時刻の複数の系列を別々に読むと、同じチャンクを系列ごとに展開する。サーバはリクエストごとに異なるインスタンスで処理され得るため、リクエスト間で展開結果を保持することを前提にできない。

## 決定

同じ group と時刻範囲に属する複数のビューを、一つのリクエストで取得できるようにする。応答は系列を識別するフレームのストリームとし、系列ごとに完了または失敗を示す。系列の変換の失敗はその系列やメッセージに限り、他の系列の表示を妨げない。切断時は読み取りを中止する。

クライアントは小さいビューの同時期の範囲取得をまとめ、画像と点群は個別に取得する。大きな応答を長く待たせたり、メモリ使用量を増やしたりしないためである。異なる group はまとめない。個別取得も利用できる。

## 結果

同じチャンクに複数トピックがあるとき、一回の読み取り内で展開を共有できる。クライアントは系列ごとの結果と失敗を振り分ける必要がある。データ形式が一括読み取りに対応しない場合は系列ごとに読み取り、同じ結果を返す。

## 採らなかった案

展開済みチャンクをサーバ内に保持する案は、リクエストが別のインスタンスに届く場合に効果を前提にできない。全系列をまとめる案は、画像や点群の大きい応答が他の系列を遅らせ、メモリ使用量を増やすため採らない。
