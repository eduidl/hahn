# 0002. 再生には記録時刻を、空間の位置合わせには計測時刻を使う

状態: 採用（2026-11-03）

[0001](0001-server-delivers-facts-client-interprets.md) を前提とする。

## 背景

録画には2種類の時刻がある。

- **記録時刻**: メッセージが書き込まれた時刻（MCAP の `log_time`）。すべてのメッセージにあり、録画の順序を決める。
- **計測時刻**: データが計測された時刻。ROS の `header.stamp` や Foxglove のスキーマの `timestamp` がこれに当たる。メッセージ内のフィールドであり、有無も時計も意味もまちまちである。

次のような、よくある場面で両者はずれる。

- ノードは入力から計算した結果を、入力の時刻を付けて少し遅れて出す。その結果を記録時刻の座標変換で置くと、遅れ×速度だけずれる。秒速 20 m で 100 ms 遅れれば 2 m になる。
- 記録済みのセンサデータを流して処理すると（`ros2 bag play` など）、記録時刻は流した時刻になり、計測時刻は元のセンサの時刻のまま残る。シミュレーション時刻ではなく自分の時計で時刻を付けるノードがあると、1つの録画に2つの時計が混ざる。
- 計測時刻はしばしば欠けているか 0 である。一部のドライバや静的な座標変換がその例である。
- シミュレーションの再起動や録画の繰り返し再生があると、1つの録画の中で計測時刻が巻き戻る。

計測時刻を run 全体の時計として扱い、記録時刻との対応をサーバが解く方法も考えられる。しかしそれには、時計のサンプルか、両方の時計が同じだという知識が要る。どちらも一般には前提にできない。

## 決定

- **再生には記録時刻を使う。** 時間軸、再生位置、履歴の範囲、最新値の問い合わせは、記録時刻で扱う。
- **計測時刻はプロトコル全体の時計にしない。** 計測時刻は普通のフィールドとして読める。プロトコルは、記録時刻と計測時刻の対応付け、時計の問い合わせ、リセット区間を定めない。記録時刻を計測時刻として、または計測時刻を記録時刻として使うことはしない。
- **サーバは、Hahn 型の値と座標変換のサンプルに両方の時刻を付ける。** 記録時刻を `time_ns`、計測時刻を `stamp_ns` とする。どのフィールドが値の計測時刻かはサーバが知っている。計測時刻が欠けているか 0 の場合は `stamp_ns` を省く。
- **空間の位置合わせには2つのモードがある。** 既定は計測時刻モードとし、[0001](0001-server-delivers-facts-client-interprets.md) に従って利用者は記録時刻モードを選べる。

  | モード | 値の時刻 | 座標変換の補間の軸 |
  |---|---|---|
  | 計測時刻 | 値の `stamp_ns` | サンプルの `stamp_ns` |
  | 記録時刻 | 値の `time_ns` | サンプルの `time_ns` |

  どちらのモードでも、時刻の比較は同じ種類の時刻どうしでだけ行う。
- **計測時刻モードで `stamp_ns` の無い値は、その値だけ記録時刻モードで置き、時刻が推定であることを画面に示す。** ただし、その値の座標系から基準の座標系までの経路に動的な座標変換が無ければ、時刻は要らないので通常どおり置く。
- **自前の値を持たないもの**（座標系の軸や、座標変換だけで動く車両など）は、再生位置の記録時刻で、記録時刻の軸を使って置く。

## 結果

- ユーザー型ごとに、どのフィールドから `stamp_ns` を取るかは、サーバの変換処理とともに定める。
- 計測時刻が座標変換と同じ時計でない場合（流したあとに時計が混ざった場合）は検出しない。計測時刻モードでは、値は誤った位置に置かれる。利用者は記録時刻モードに切り替えて回避できる。
- 記録時刻モードと、`stamp_ns` の無い値の置き方は、処理の遅れの分だけずれる。
- 自前の値を持たないものは、再生位置の記録時刻で座標変換を補間して置かれ、1つの計測時刻にはそろわない。その差は座標変換サンプル自身の記録の遅れ程度である。
- 計測時刻の巻き戻りは既知の制限とする。計測時刻モードでは、録画の別の区間のサンプルに一致し得る。実例が必要になれば、リセットのモデルとともに見直す。

## 採らなかった案

- run 全体の計測時計を設ける。サーバが記録時刻を計測時刻へ対応付ける問い合わせを提供し、計測時刻の巻き戻りで録画をリセット区間に分ける。時計のサンプルなど、録画一般について前提にすることが多すぎるため採らない。
- 記録時刻だけで空間の位置合わせをする。処理の遅れで、計算結果の値が誤った位置に置かれるため採らない。記録時刻モードとして選べるようにはする。
- 座標変換サンプルを経由して記録時刻から計測時刻を推定し、計測時刻の軸で座標変換を引く。記録時刻の軸で直接補間するのと精度は変わらず、計測時刻の無い座標変換サンプルを使えないため採らない。
- 計測時刻を再生の軸にする。計測時刻は欠けたり、時計が混ざったり、単調でなかったりするが、記録時刻は必ずあり、順序も決まっているため採らない。
