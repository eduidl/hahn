# 0003. 座標変換はサンプルとして渡し、クライアントが解く

状態: 採用（2026-11-03）

[0001](0001-server-delivers-facts-client-interprets.md) と [0002](0002-time-model.md) を前提とする。

## 背景

座標変換は表示する対象ではなく、ほかの値を読むための前提である。複数のトピック（`/tf`、`/tf_static` など）に分かれて記録され、1つのメッセージが一部のフレームしか含まないこともある。そのため、トピック単位ではなく、まとめて1つのフレームのグラフとして扱う必要がある。グループの分け方はサーバが決めるので、どのグループのビューも同じグラフを参照できなければならない。

0001 により、サーバは録画から読み取った事実としてサンプルを渡し、補間や基準の座標系の選択はクライアントが受け持つ。0002 により、位置合わせには計測時刻モードと記録時刻モードがあり、座標変換はそれぞれ計測時刻（`stamp_ns`）または記録時刻（`time_ns`）の軸で補間する。

記録は数時間に及ぶことがあり、動的な座標変換は数十 Hz で記録されることが多い。run 全体のサンプルを一度に渡すことはできない。

## 決定

### グラフの範囲

- run は1つのフレームのグラフを持つ。開いているかどうかに関係なく、run のすべてのグループから集める。読めないグループは除き、除いたことをフレームの一覧で示す。
- どのトピックをグラフに使うかはサーバが決める。それらのトピックも、通常のメッセージとして読める。
- 座標は右手系で、単位はメートルとラジアンとする。異なる規約の録画はサーバが変換する。

### サーバが渡すもの

- **分類**: サーバは子フレームごとに、静的か動的かのどちらか一方に分類する。同じ子フレームが両方に現れることはない。
- **静的な座標変換**: 子フレームごとに1つ。記録時刻、録画内の順序、run のグループの順序で最後のものを使う。時刻を持たない。run 全体を一度に取得する。
- **動的なサンプル**: 子フレーム、親フレーム、並進、回転、記録時刻（`time_ns`）、計測時刻（`stamp_ns`）を持つ。重複を除かず、同じ時刻のサンプルも別の行として渡す。記録時刻の範囲を指定して取得し、行は記録時刻、録画内の順序、run のグループの順序で並べる。計測時刻が欠けているか 0 のサンプルも、`stamp_ns` を省いて渡す。記録時刻モードではそれも使う。
- **フレームの一覧**: run のすべてのフレームについて、静的か動的か、記録されたすべての親フレーム（最初に記録された順）、除いたサンプルの数を渡す。親フレームは途中で変わり得るので、1つに絞らない。クライアントは、サンプルを取得せずに基準の座標系の選択肢を示せる。
- 数値が有限でないサンプルや、親子どちらかのフレームが無いサンプルは、座標変換として成り立たないので渡さない。除いたサンプルの数を、フレームの一覧で子フレームごとに示す。

### 取得の範囲

- 動的なサンプルは記録時刻の範囲で取得する。計測時刻の範囲では取得しない。計測時刻は時計が混ざったり巻き戻ったりし得るが、記録時刻は必ずあり、再生の軸とも一致する。
- 値の計測時刻は記録時刻より前にずれるので、クライアントは表示に必要な範囲より前後に余裕を持たせて取得する。余裕の幅はクライアントが決める。
- サーバは量の上限や間引きを設けない。クライアントが再生位置の周りを区切って取得する。

### クライアントが解く規則

ある時刻での、ある子フレームの座標変換を次の規則で求める。補間の軸は、計測時刻モードでは `stamp_ns`、記録時刻モードでは `time_ns` とし、規則はどちらの軸でも同じである。

- その子フレームのサンプルのうち、軸の時刻を持つものだけを使う。計測時刻モードでは `stamp_ns` の無いサンプルを使わず、あることを画面に示す。
- 軸の時刻が同じサンプルが複数あるときは、渡された順で最後のものを使う。
- 前後のサンプルの間を補間する。並進は線形、回転は球面線形補間で短い方を回る（`q` と `-q` は同じ回転である）。
- 前後のサンプルで親フレームが違うときは補間しない。前のサンプルを次のサンプルまでそのまま使う。
- 外挿しない。最初のサンプルより前、最後のサンプルより後の時刻では、その子フレームの座標変換は無い。
- 利用者は補間を切れる。その場合も適用範囲は補間するときと同じとし、前のサンプルをそのまま使う。
- フレームの循環は不正なデータである。循環上のフレームをどちら向きに解くかは定めない。
- 基準の座標系につながらないフレームと、座標変換が無い時刻にかかるフレームは、その時刻では置けない。

## 結果

- 姿勢などの値を別の座標系で表示するのはクライアントの仕事である。軌跡は、各値の時刻（モードに応じて `stamp_ns` または `time_ns`）で座標変換を引いて描く。
- 基準の座標系の切り替え、補間の有無、位置合わせの時刻の切り替えは、取得済みの範囲ならサーバへの問い合わせなしに反映される。
- 再生位置を大きく動かすと、新しい範囲のサンプルを取得するまで座標変換が無い状態になり得る。
- サンプルの量は記録の頻度と範囲に比例する。取得の区切り方は、実際の記録で測って調整する。
- 計測時刻が巻き戻る録画では、別の区間のサンプルが同じ計測時刻に並び、計測時刻モードでは誤った座標変換を使い得る（0002 の既知の制限）。

## 採らなかった案

- サーバがある時刻の座標変換を解いて返す。0001 の理由で採らない。
- 動的なサンプルを計測時刻の範囲で取得する。計測時刻の対応付けを前提にしない 0002 と合わないため採らない。
- run 全体のサンプルを一度に渡す。長い記録で量が大きすぎるため採らない。
- サーバで間引く。間引き方は解釈であり、補間の結果も変わるため採らない。

## 未決

- 同じ子フレームが静的なトピックと動的なトピックの両方に現れたときの分類規則を、サーバの仕様として定める。
- 取得の余裕の幅と区切り方の既定値は、実装と計測で決める。
