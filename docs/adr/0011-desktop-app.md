# 0011. デスクトップアプリは、利用者が選んだ録画ファイルを同じプロセスの 127.0.0.1 のサーバで配信し、Tauri のウィンドウで開く

状態: 採用（2026-11-12）

## 背景

Hahn は、録画を読む HTTP サーバと、ブラウザで動くクライアントからなる。利用者は、録画を置いたディレクトリを指定してサーバを起動し、ブラウザで URL を開き、一覧から run を選ぶ。

手元の録画を一つ見たいだけの利用者には、この手順は長い。録画をディレクトリに置き、端末でサーバを起動し、ブラウザで開き、一覧から選ぶ必要がある。デスクトップのアプリケーションなら、ほかのアプリと同じように、OS のファイル選択ダイアログで録画を選んだり、ファイルをウィンドウにドロップしたりして開くほうが自然である。この場合、サーバが一覧として返す run は選んだ録画だけなので、run の一覧から選ぶ画面は役に立たない。

Tauri は、OS の WebView でウェブのクライアントを表示し、Rust のプロセスと組み合わせてデスクトップアプリにする仕組みである。サーバは Rust のライブラリとしても使えるので、同じプロセスに組み込める。

クライアントは、データを次の前提で取得・保存している。

- 同じオリジンの `/api` へ HTTP で要求し、応答を受け取りながら少しずつ表示する。大きな応答は数百 MB になる。
- 作業領域（ウィジェットの配置、系列、開いている run とグループ）を、ブラウザのオリジンごとの保存領域に保存し、次に開いたときに復元する。

Tauri でクライアントを表示する方法は二つある。

1. Tauri が用意する独自のスキーム（`tauri://` など）でクライアントのファイルを配信し、API も独自のスキームのハンドラで答える。
2. アプリの中で 127.0.0.1 に HTTP サーバを立て、ウィンドウでその URL を開く。

独自スキームのハンドラは、応答の本体を一度に返す。応答を送りながら表示するクライアントの読み方が使えず、大きな応答をすべてメモリに載せてから返すことになる。

## 決定

### 構成

- デスクトップアプリは、`hahn` クレートのサーバと、ビルド済みのクライアントを一つのアプリケーションにまとめる。
- 起動すると、同じプロセスで 127.0.0.1 に HTTP サーバを立て、API とクライアントのファイルを配信する。ウィンドウはその URL を開く。
- API と HTTP の契約は、ブラウザで使うときと同じにする。デスクトップアプリのための API は足さない。

### 録画の開き方

- デスクトップアプリは、一度に一つの録画ファイルを開く。録画は、起動時のコマンドライン、ヘッダの run を選ぶボタンから出す OS のファイル選択ダイアログ、ウィンドウへのファイルのドロップのどれかで指定する。
- 録画を指定せずに起動したときは、run を開いていない状態でウィンドウを開く。この状態では、サーバは空のディレクトリを配信し、run の一覧は空になる。ダイアログを選ばずに閉じても、開いている状態は変わらない。
- 複数のファイルが一度にドロップされたときは、そのうち最初の MCAP ファイルを開く。MCAP ファイルが無ければ最初のファイルを開こうとし、開けない理由を示す。
- Windows では、ファイルのドロップを受け付けない。WebView2 では、アプリがドロップされたファイルを受け取るあいだ、ページの中のドラッグ＆ドロップ（トピックやウィジェットのドラッグ）が使えなくなるためである。ほかの OS では、アプリが受け取るのは外から持ち込まれたファイルだけで、ページの中のドラッグ＆ドロップは影響を受けない。
- サーバは、録画のディレクトリの代わりに録画ファイルを一つ受け取れる。そのファイルが唯一の run になり、run とグループの名前と ID は、そのファイルを含むディレクトリを指定したときと同じになる。同じファイルを開き直せば、保存された作業領域がそのまま当てはまる。
- 別の録画を開くと、サーバはそれ以降、新しい録画だけを配信する。サーバを止めずに中身を差し替えるので、ポートとオリジンは変わらない。
- 録画を開いたら、ウィンドウを `/?run=<id>` に移動する。クライアントは、アドレスで指定された run を、一覧を出さずに開く。保存された run と異なれば、ブラウザで別の run を選んだときと同じく、ウィジェットを残して系列を新しい run のグループへ移す。
  - この指定はデスクトップアプリに限らない。ブラウザでも、run を開くリンクとして使える。ブラウザでは指定をアドレスから取り除き、再読み込みでは保存された作業領域を復元する。
  - デスクトップアプリでは、開く run をアドレスだけで決める。指定はアドレスに残し、再読み込みでも同じ run を開く。指定が無ければ run を開かず、ブラウザに保存された前回の run も開かない。前回の run がアプリの配信している録画と一致するとは限らないからである。ウィジェットの配置と系列は残す。
- ページを読み込み直すので、前の録画のために持っていたデータはクライアントから消える。異なる場所にある同じ名前のファイルは同じ ID になるが、古いデータが新しい録画のものとして残ることはない。

### クライアントとの連携

- クライアントは、Tauri の WebView の中で動いているかを見分ける。その場合だけ、ヘッダの run を選ぶボタンで run の一覧を出さず、アプリのコマンドを呼んでファイル選択ダイアログを出させる。
- クライアントからアプリへの呼び出しは、このコマンドだけとする。データはこれまでどおり HTTP で受け取る。
- Tauri は既定で、外部の URL から読み込んだページにコマンドの呼び出しを許さない。このコマンドだけを、127.0.0.1 から読み込んだメインのウィンドウに許す。ウィンドウはサーバのオリジン以外へ移動しない（後述）ので、ほかのページはこのコマンドを呼べない。

### 設定

- 時間帯は、指定がなければ、そのコンピュータの時間帯を使う。手元の録画を手元で見る用途を想定しているためである。
- 録画を読めないときは、理由をダイアログで示し、それまで開いていた状態を保つ。クライアントが見つからない、ポートで待ち受けられないなど、ウィンドウを開けないときは、理由を示して終了する。

### ポート

- 既定では 127.0.0.1 の決まったポートで待ち受ける。作業領域はオリジンごとに保存されるので、毎回同じポートを使えば、前回の作業領域が復元される。
- そのポートが使用中なら、空いている任意のポートで待ち受ける。この場合、前回の作業領域は復元されない。起動できないよりは、復元されないほうがよいからである。
- 127.0.0.1 以外では待ち受けない。サーバには認証が無いためである。

### 外部へのリンク

- ウィンドウの中で、サーバと異なるオリジンへ移動しようとしたときは、移動せずに既定のブラウザで開く。地図の出典のリンクなどを開いたときに、ウィンドウが Hahn に戻れなくなるのを避けるためである。

## 結果

- 応答を送りながら表示する読み方と、作業領域の保存が、ブラウザと同じように働く。
- クライアントとサーバのテストが、デスクトップアプリで表示される内容も確かめる。デスクトップアプリ固有の確認は、ビルドできること、指定した録画を開けること、別の録画に切り替えられること、ドロップしたファイルを開けることに限られる。
- 一つの run に複数のグループを持つ録画（ディレクトリや rosbag2 の bag）は、デスクトップアプリでは開けない。必要になれば、ファイルの複数選択やディレクトリの選択として別に決める。
- サーバは 127.0.0.1 のポートで待ち受けるので、同じコンピュータのほかのプロセスやブラウザからも API に届く。これはブラウザで使うときと同じである。
- ビルドには、OS ごとの WebView の開発用ライブラリが要る。通常の確認の手順はそれを必要としないままにし、デスクトップアプリのビルドは別の手順とする。
- 表示は OS の WebView に依存する。Linux の WebKitGTK など、ブラウザと描画や性能が異なる場合がある。
