# 0007. Hahn 型の値は有限の数だけを持ち、クライアントは知らない値を飛ばして続ける

状態: 採用（2026-11-03）

[0001](0001-server-delivers-facts-client-interprets.md)、[0005](0005-hahn-types.md)、[0006](0006-message-values.md) を前提とする。

## 背景

Hahn 型の値は、3D 表示、地図、画像への投影でそのまま描かれる。メッセージの値（[0006](0006-message-values.md)）と違い、NaN や欠けた値を描画の手前で一つずつ確かめさせるのは、クライアントにとって負担が大きく、見落とすと描画が壊れる。一方、記録には NaN がよく含まれる。たとえば深度カメラやライダーの点群は、計測できなかった点の座標を NaN にする。

また、Hahn 型やその中の値の種類（画像の形式、歪みのモデル、注釈の種類など）は、あとから増える。サーバとクライアントの組み合わせによっては、クライアントが知らない値を受け取る。そのときに表示全体が止まると困る。

## 決定

### 数値

- Hahn 型の値の JSON に含まれる数は、すべて有限であり、`null` にならない。
- 必須の数が欠けているか有限でないメッセージは、変換の失敗とする。その値は、エラーの説明を持つフレームとして渡し、ストリームは続ける。1つのメッセージをデコードできない場合も、そのメッセージの変換の失敗とする（[0008](0008-errors.md)）。
- 任意の数が有限でなければ、その数を省く。
- まとまりの型（[0005](0005-hahn-types.md)）では、要素が互いに独立であれば、不正な要素だけを除いて値を渡す。除いた要素の数を値に含める。`poses` の姿勢、`bbox3d` の箱、`image_annotations` の注釈、`geo` の地物、`pointcloud` の点がこれに当たる。点群では、座標が有限でない点を除く。
- 要素の中の点の並び（注釈の折れ線や `geo` の線・多角形の点）に不正な点があれば、その要素を不正として除く。点だけを除くと形が変わり、誤ったものを描くためである。
- 値そのものが1つの並びである型では、不正な要素が1つでもあれば値全体を変換の失敗とする。`path` の姿勢がこれに当たる。
- バイナリで渡す点群の座標以外のフィールド（強度など）は、記録された値のまま渡す。NaN を含み得る。
- 回転を表す四元数は記録されたまま渡す。正規化と、長さが 0 の四元数の扱いはクライアントが行う。クライアントは長さ 0 の四元数を回転なしとして扱う。

### 知らない値

サーバは、次のものを予告なく増やしてよい。既にあるものの意味は変えない。

- Hahn 型
- オブジェクトのフィールド
- 文字列で種類を示す値（画像の形式、歪みのモデル、注釈の種類、点群のフィールドの型、フィールドの `data_type`、ストリームのイベントの種類など）

クライアントは、知らないものを受け取ったら次のように扱い、ほかの表示を続ける。

| 知らないもの | クライアントの扱い |
|---|---|
| Hahn 型 | そのビューを選択肢に出さない |
| オブジェクトのフィールド | 無視する |
| 画像の形式 | その画像を表示できないことを示す |
| 歪みのモデル | そのキャリブレーションを使わない（[0004](0004-camera-calibration.md)） |
| 注釈や地物の種類 | その注釈や地物だけを飛ばし、残りを描く |
| 点群のフィールドの型 | そのフィールドだけを飛ばし、座標と知っているフィールドを使う |
| フィールドの `data_type` | 型に応じた操作（時系列など）の対象にしない。値はメッセージとして読める |
| ストリームのイベントの種類 | そのイベントを飛ばして読み続ける。バイナリのフレームは長さに従って本体ごと飛ばす。完了とも失敗とも扱わない |

ストリームが完了も失敗も示さずに終わったら、知らないイベントを受け取っていても、失敗として扱う。

## 結果

- クライアントは、Hahn 型の値の数を描く前に確かめなくてよい。
- 点群の NaN の点は除かれ、除いた数が分かる。クライアントはそれを表示できる。
- 経路の一部が壊れたメッセージは、そのメッセージだけが変換の失敗になり、前後の表示は続く。
- サーバに Hahn 型や種類を足しても、古いクライアントは知らないものを飛ばして動き続ける。
- 既にある値の意味を変える変更や、必須のフィールドを除く変更は、この規則では扱えない。

## 採らなかった案

- Hahn 型の値でも NaN や `null` を許し、クライアントが確かめる。確かめ漏れが描画の崩れになり、すべての表示で同じ確認が要るため採らない。
- 不正な要素を含むまとまりを、常に値全体の失敗とする。NaN の点を含む点群がほとんど表示できなくなるため採らない。
- 不正な要素を、何も示さずに除く。データの欠けに利用者が気づけないため採らない。
- 知らないものを受け取ったら、表示全体を失敗とする。サーバだけを更新したときに、関係のない表示まで止まるため採らない。

## 未決

- 既にある値の意味を変える変更や必須のフィールドを除く変更を、どう扱うか（版の取り決めなど）は、要る場面が出たら別に定める。
