# 0004. カメラキャリブレーションは独立した値とし、画像との対応はサーバが示してクライアントが選ぶ

状態: 採用（2026-11-03）

[0001](0001-server-delivers-facts-client-interprets.md)、[0002](0002-time-model.md)、[0003](0003-transforms.md) を前提とする。

## 背景

画像の上に点群を投影したり、3D 表示に画像を置いたりするには、その画像のカメラキャリブレーション（カメラ行列と歪み係数からなる内部パラメータ）が要る。キャリブレーションは画像とは別のトピックに記録される。ROS では画像と同じ名前空間の `camera_info`、Foxglove では `foxglove.CameraCalibration` のトピックが一般的である。

画像とキャリブレーションの対応には、次の難しさがある。

- 対応は録画の慣習に依存する。トピックの名前空間、`frame_id`、スキーマの種類などから推し量るしかない。
- 同じカメラの未補正（raw）の画像と補正済み（rectified）の画像は、同じ `frame_id` と同じキャリブレーションのトピックを共有することが多い。しかし、使う値が違う。未補正の画像にはカメラ行列 `K` と歪み係数を、補正済みの画像には射影行列 `P` を歪みなしで使う。`frame_id` だけでは区別できない。
- 切り出しや縮小をした画像には、元の解像度のキャリブレーションはそのまま使えない。
- キャリブレーションは時間とともに変わり得る。ただし多くの場合は一定で、画像と同じ頻度で繰り返し記録される。

慣習を知っているのはサーバである。一方、推し量った対応が誤っている場合や、別のキャリブレーションで見比べたい場合に、利用者が選び直せることも要る。

## 決定

### キャリブレーションの値

- キャリブレーションは独立した Hahn 型（`camera_calibration`）のビューとする。画像の値には含めない。
- 値は、記録時刻（`time_ns`）、計測時刻（`stamp_ns`、無ければ省く）、`frame_id`、幅と高さを持つ。さらに、未補正の画像用のカメラ行列と歪み係数、補正済みの画像用の射影行列を、記録にあるものだけ持つ。
- 歪みのモデルは名前で示す。クライアントが知らないモデルのキャリブレーションは使わない。歪みを無視すると、描くものが誤った位置に置かれるためである。

### 画像との対応

- サーバは、画像のビューごとに、対応すると判断したキャリブレーションのビューを示す。別のグループのトピックでもよい。判断できなければ示さない。判断の規則はサーバが録画の慣習に従って定める。
- サーバは、画像のビューごとに、画素が未補正か補正済みかを、分かれば示す。
- クライアントは、サーバの示した対応を既定として使う。利用者は、run の中の別のキャリブレーションのビューを選んだり、キャリブレーションを使わないことにしたりできる。また、未補正か補正済みかも選び直せる。
- 未補正か補正済みかが分からない画像は、未補正として扱う。
- Rust サーバは、画像のトピック名から末尾の `compressed` と `image` で始まる区切りを除いたものをカメラとし、その直下にキャリブレーションのトピックがちょうど1つあれば対応させる。`/cam/image_raw` と `/cam/camera_info`、`/cam` と `/cam/calibration` がこれに当たる。除いた区切りに `rect` があれば補正済み、`raw` があれば未補正とする。

### 画像ごとのキャリブレーションの選び方

クライアントは、画像ごとに次の規則でキャリブレーションの値を選ぶ。

- 計測時刻モードでは、画像とキャリブレーションの値の両方に `stamp_ns` があれば `stamp_ns` で比べ、どちらかに無ければ `time_ns` で比べる。記録時刻モードでは `time_ns` で比べる。この比べ方はキャリブレーションの選択にだけ使い、画像を置く時刻は [0002](0002-time-model.md) のモードに従う。
- 画像の時刻以前で最新のキャリブレーションの値を使う。時刻が同じ値が複数あれば、渡された順で最後のものを使う。画像の時刻以前に値が無ければ、最初の値を使う。
- キャリブレーションの幅と高さが画像と違う場合は使わない。
- 未補正の画像にはカメラ行列と歪み係数を、補正済みの画像には射影行列を歪みなしで使う。必要な値がキャリブレーションに無ければ使わない。
- キャリブレーションを使えない場合も画像は表示する。投影や 3D での配置をしないことと、その理由を画面に示す。

## 結果

- キャリブレーションの値は、画像とは別に取得する。一定のことが多いので、取得の量は小さい。
- 画像の値はキャリブレーションに依存しない。キャリブレーションを読めなくても画像の表示には影響しない。
- 対応の判断が誤っても、利用者が画面で直せる。
- 未補正か補正済みかの判断を誤ると、投影が歪みの分だけずれる。利用者は画面で選び直せる。
- ドライバが画像と同じ計測時刻をキャリブレーションに付ける記録では、計測時刻どうしで対応する。静的な発行元が計測時刻を付けない記録では、記録時刻で選ばれ、値が一定なので結果は正しい。
- 録画の冒頭で、最初のキャリブレーションの値が最初の画像より後に記録されていても、冒頭の画像に最初の値が使われる。キャリブレーションが変わるシステムでは、これは前方への推測になる。
- キャリブレーションが変わるシステムで記録時刻で比べる場合、新しい値が使われ始めるのが記録の遅れの分だけずれる。

## 採らなかった案

- サーバが画像ごとにキャリブレーションを解き、画像の値に含める。クライアントは単純になるが、対応や時刻の選び方を利用者が変えられず、[0001](0001-server-delivers-facts-client-interprets.md) の分担に合わないため採らない。
- `frame_id` だけで対応を決める。未補正と補正済みの画像を区別できないため採らない。
- 解像度が違うキャリブレーションを、比率で拡大縮小して使う。切り出しと縮小を区別できず、誤った投影を黙って出すため採らない。
- 計測時刻の無いキャリブレーションに、サーバが計測時刻 0 を付けて渡す。計測時刻が無いことは省いて伝えるという [0002](0002-time-model.md) の決定と食い違うため採らない。
