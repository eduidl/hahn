# 0006. メッセージの値は、型と区別できる情報を失わない JSON で表す

状態: 採用（2026-11-03）

[0001](0001-server-delivers-facts-client-interprets.md) を前提とする。

## 背景

メッセージの値は、時系列、テーブル、メッセージの表示で読まれる。サーバはユーザー型のメッセージを JSON に変換して渡し、クライアントはトピックのスキーマ（フィールドの型）とあわせて読む。JSON には次の制約がある。

- 数値は倍精度の浮動小数点数として読まれることが多く、64 ビット整数を正確に表せない。
- NaN と無限大を表せない。
- 単精度の浮動小数点数をそのまま倍精度として書くと、`0.1` が `0.10000000149011612` になる。

また、長いリストや文字列をそのまま渡すと、表示に要らない量を転送することになる。

値の表し方を決めるうえで、次の区別が要る。

- 欠けている値と、NaN と、無限大は意味が違う。時系列ではどれも点を打たないが、テーブルでは区別して見せたい。
- 短くした値は、元の値ではないと分からなければならない。
- enum は数値で記録されている。名前で表示したい一方で、時系列では数値として描きたい。

## 決定

### 数値

- 64 ビット整数（`int64`、`uint64`）は 10 進の文字列で表す。ほかの整数は JSON の数値で表す。
- 有限の浮動小数点数は JSON の数値で表す。単精度の値は、単精度に戻したときに同じ値になる最短の 10 進表記で書く。`0.1` は `0.1` と書く。
- NaN と無限大は、文字列 `"NaN"`、`"Infinity"`、`"-Infinity"` で表す。
- 欠けている値は `null` で表す。`null` は欠けていることだけを意味する。

### 時刻

- ナノ秒単位の時刻は、プロトコルのどこでも 10 進の文字列で表す。メッセージの行の記録時刻、Hahn 型の値の記録時刻（`time_ns`）と計測時刻（`stamp_ns`）、座標変換のサンプルの時刻、時刻を指定する問い合わせがこれに当たる。倍精度の数値では正確に表せない大きさだからである。

### enum

- enum は記録された数値で表す。数値の表し方は、その enum の元の整数の型に従う。
- 名前の表示はクライアントが行う。スキーマの `enum_values` から数値に対応する名前を引く。同じ数値に複数の名前があれば、`enum_values` で最初の名前を使う。定義されていない数値は、数値のまま表示する。

### 短くした値

長い値は、利用者が完全な値を求めない限り短くして渡す。短くした値は、それと分かる形で表す。

| 対象 | 条件 | 形 |
|---|---|---|
| リスト、配列、マップ | 101 要素以上 | `{"$truncated": true, "length": 全要素数, "items": [先頭 100 要素]}` |
| バイト列 | 常に | `{"$bytes": 全バイト数, "head": [先頭 32 バイト]}` |
| 文字列 | 10,000 文字を超える | `{"$truncated": true, "length": 全文字数, "text": "先頭 10,000 文字"}` |

- クライアントは、フィールドの型が文字列、リスト、配列、マップ、バイト列であるのにオブジェクトが来たことで、短くした値だと分かる。
- enum の値は数値なので短くしない。

### 構造

- 構造体は、フィールド名をキーとするオブジェクトで表す。リストの中でも同じとする。
- マップは `[キー, 値]` の組の配列で表し、キーの型を保つ。
- `json` 型のフィールドは JSON の文書を文字列として持つ。短くして渡すときは、文書を解析した値を、上と同じ制限で渡す。解析できない文字列は文字列のまま渡す。

## 結果

- 浮動小数点数のフィールドの値は、数値、NaN と無限大の文字列、`null` のいずれかになる。クライアントは型に応じて読み分ける。
- 時系列は、NaN、無限大、欠けた値のどれにも点を打たない。テーブルはそれぞれを区別して表示できる。
- 単精度の値は、記録された値と同じ桁で表示される。JSON の数値として読むと倍精度の近い値になるが、表示と描画には差が出ない。
- enum は時系列にそのまま描け、テーブルでは名前で表示される。名前の選び方はクライアントの表示の規則であり、サーバの変換には現れない。
- `json` 型のフィールドを解析した値に `$truncated` や `$bytes` を含むオブジェクトがあると、短くした値と区別できない。完全な値を求めれば元の文字列で読める。

## 採らなかった案

- NaN、無限大、欠けた値をすべて `null` で表す。テーブルで区別できないため採らない。
- 単精度の値を倍精度の最短表記で書く。記録にない桁が表示されるため採らない。
- enum を名前の文字列で表す。時系列で描くには数値に戻す必要があり、同じ数値に複数の名前がある場合の選び方をサーバが決めることになるため採らない。名前の選び方は表示の解釈であり、[0001](0001-server-delivers-facts-client-interprets.md) によりクライアントが受け持つ。
- 短くした文字列を末尾の `…` で示す。元の文字列が `…` で終わる場合と区別できないため採らない。
