# 0008. エラーは固定のコードで識別し、空の結果はエラーにしない

状態: 採用（2026-11-03）

[0003](0003-transforms.md)、[0007](0007-view-values-and-unknowns.md) を前提とする。

## 背景

クライアントは、失敗の種類によって画面の振る舞いを変える。run が消えていれば一覧に戻り、トピックが無ければその表示だけを諦め、録画が読めなければ理由を示す。説明の文章を解析して種類を見分けると、文章を直しただけで振る舞いが変わる。

ストリームでは、送り始めたあとに HTTP の状態を変えられない。送り始めたあとの失敗は、ストリームの中で伝える必要がある。

また、「該当するものが無い」ことと「失敗した」ことは違う。範囲にメッセージが無いのは正常な結果であり、録画が読めないのは失敗である。読めないことを空の結果として返すと、利用者はデータが無いと誤解する。

## 決定

### 形

- HTTP のエラーの本文は、固定のコード `code` と、人が読む説明 `error` を持つ。
- ストリームの終わりを示すエラーのイベントは、同じ `code` と、人が読む説明 `message` を持つ。
- クライアントはコードで失敗の種類を見分け、説明の文章を解析しない。
- 1つのメッセージに限られた失敗は、ストリームを終わらせない。メッセージをデコードできない場合と、Hahn 型に変換できない場合（[0007](0007-view-values-and-unknowns.md)）がこれに当たる。ビューでは説明を持つフレームとして、メッセージの履歴では値の代わりに説明を持つ行として渡し、ストリームは続く。最新のメッセージを求めてそれが該当した場合も、説明を持つ結果を正常に返す。
- 1つのメッセージを越えて読めない場合は `recording_unreadable` とする。録画を開けない場合、索引やチャンクを読めない場合、トピックのスキーマを解釈できない場合がこれに当たる。送り始めたあとなら、ストリームを終わらせるエラーとして伝える。

### コード

| HTTP の状態 | コード | 意味 |
|---|---|---|
| 400 | `invalid_request` | 問い合わせの形が不正、値が不正、組み合わせが不正、または必須の指定が無い |
| 404 | `run_not_found` | run が無い |
| 404 | `group_not_found` | run の中にグループが無い |
| 422 | `unknown_topic` | グループの中にトピックが無い |
| 422 | `unknown_field` | フィールドの道筋の形は正しいが、スキーマに無い。構造体でない値をたどった場合も含む |
| 422 | `unknown_meta_field` | メタフィールドが無い |
| 422 | `unknown_view` | トピックにビューが無い |
| 422 | `invalid_selection` | フィールドは正しいが、求めた操作に使えない |
| 422 | `recording_unreadable` | 録画を開けない、または1つのメッセージを越えて読めない。壊れた録画や対応していない形式を含む |
| 500 | `internal_error` | 録画や指定に原因の無い、サーバの予期しない失敗 |

- URL の道筋で指定するもの（run、グループ）が無ければ 404、問い合わせの指定で選ぶもの（トピック、フィールド、ビュー）が無ければ 422 とする。
- サーバはコードを増やしてよい。クライアントは知らないコードを、種類の分からない失敗として扱う。空の結果としては扱わない。

### 空の結果

- 存在して読めるものに該当するものが無いのは、正常な結果である。メッセージの履歴は行の無い完了、最新のメッセージは `null`、ビューは完了だけになる。
- メッセージの無いグループの情報は、正常な結果として返し、時間の範囲を省く。
- 存在しないトピックは、グループにメッセージが無くても `unknown_topic` とする。
- 読めない録画を、空の結果として返さない。`recording_unreadable` とする。
- 例外として、フレームのグラフ（[0003](0003-transforms.md)）は読めないグループを除いて作る。除いたグループは、フレームの一覧で示す。

## 結果

- クライアントは、コードに応じて画面の振る舞いを決められる。説明の文章は自由に直せる。
- 空のグループの情報も正常に返るので、クライアントは空のグループを失敗と区別して表示できる。
- 録画が読めないことと、データが無いことを、利用者が取り違えない。
- フレームのグラフに使えなかったグループがあることを、利用者に示せる。

## 採らなかった案

- 説明の文章だけを返し、クライアントが HTTP の状態で見分ける。同じ 422 の中で、トピックが無いのか録画が読めないのかを見分けられないため採らない。
- メッセージの無いグループの情報を失敗として返す。グループは存在して読めており、空であることは正常な結果であるため採らない。
- 読めない録画を空の結果として返し、表示を続ける。利用者がデータが無いと誤解するため採らない。
